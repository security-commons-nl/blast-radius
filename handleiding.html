blastradius.

Wat valt er om als dit uitvalt? De blast radius van je CI-landschap, uit een export die je al hebt.

Wat het doet

Als een server, database of koppeling uitvalt, welke applicaties en bedrijfsprocessen vallen dan mee om? Die keten zit vaak wel in een CMDB, maar niemand rekent hem door. blastradius leest een landschapsexport en maakt de keten zichtbaar: een interactieve graaf, per component de blast radius, en de kritieke processen die op een enkele applicatie steunen.

Deterministisch. De blast radius is de transitieve keten omhoog door de graaf. Dezelfde invoer geeft dezelfde uitkomst. Er zit geen model tussen de cijfers; de optionele AI-duiding komt er los bovenop.

Het model

Een landschap is een graaf met drie lagen. Een relatie from -> to betekent "from draagt to": valt from uit, dan wordt to geraakt.

LaagTypeVoorbeeld
Infrastructuurciserver, database, netwerk, DigiD-koppeling
Applicatieappzaaksysteem, betaalengine, BRP
Procesprocespaspoortuitgifte, uitkeringen (markeer kritieke met kritiek)

Edges lopen van onder (ci) naar boven (proces). De blast radius van een component is alles wat je van daaruit stroomopwaarts kunt bereiken.

In 2 stappen

# 1 · exporteer je landschap naar JSON of CSV (zie hieronder)
# 2 · analyseer
python -m blastradius landschap.json --out rapport.html

Meteen uitproberen zonder eigen data: python -m blastradius testdata/landschap.json --out voorbeeld.html. De meegeleverde testdata is een klein verzonnen gemeentelijk landschap.

Invoer: JSON

Het primaire formaat, met expliciete nodes en edges.

{
  "naam": "Mijn landschap",
  "nodes": [
    {"id": "ci-db",  "label": "db01",         "type": "ci"},
    {"id": "app-x",  "label": "Applicatie X", "type": "app"},
    {"id": "proc-y", "label": "Proces Y",     "type": "proces", "kritiek": true}
  ],
  "edges": [
    {"from": "ci-db",  "to": "app-x"},
    {"from": "app-x",  "to": "proc-y"}
  ]
}

Invoer: CSV uit een CMDB

Een regel per relatie, de nodes worden eruit afgeleid. Handig als je een koppelingen-export uit een CMDB of spreadsheet hebt.

from,from_label,from_type,to,to_label,to_type,relatie
ci-netwerk,netwerk-core,ci,ci-db,db01,ci,ondersteunt
ci-db,db01,ci,app-x,Applicatie X,app,ondersteunt
app-x,Applicatie X,app,proc-y,Proces Y,proces,ondersteunt

Labels en relatie zijn optioneel. Kritieke processen markeer je met een kolom to_kritiek (waarde ja, true of 1).

Het rapport lezen

Het HTML-bestand is self-contained: geen externe fonts of scripts, geen netwerkverkeer. Het opent in elke browser en print naar A4.

1

Klik een component

Klik een server, database of applicatie in de graaf. Alles wat erbovenop hangt licht rood op, en het paneel eronder toont hoeveel componenten en welke processen stilvallen. Zo zie je de blast radius van dat ene component.

2

Klik een proces

Klik een proces bovenin. Nu licht de keten eronder op: alle infrastructuur en applicaties waar het proces op steunt. Zo zie je in een oogopslag waar de kwetsbaarheid van een proces zit.

Onder de graaf staan twee tabellen: de ranglijst blast radius (welk component raakt de meeste kritieke processen) en de kwetsbare processen (kritiek, maar zonder redundantie in de applicatielaag).

Een component dat overal bovenaan de ranglijst staat is meestal een gedeelde onderlaag (kernnetwerk, centrale authenticatie). Dat is precies waar je continuiteitsmaatregelen als eerste op richt.

AI-duiding en de API-key

De cijfers komen altijd uit de graaf, nooit uit een model. De vlag --ai voegt een sectie toe die het verhaal voor een bestuurder vertelt. Zonder key werkt alles door; je mist enkel die sectie.

1 · Een API-key aanmaken

Maak een account op console.anthropic.com, ga naar API Keys en maak een nieuwe sleutel. Die begint met sk-ant-. Kopieer hem meteen, want hij is later niet meer op te vragen. Het model rekent per rapport af; een duiding is klein (grofweg een cent of enkele centen per run).

Behandel de key als een wachtwoord. Zet hem nooit in een script, een rapport of een gedeelde map. Alleen als omgevingsvariabele, op de machine waar je de analyse draait.

2 · De key als omgevingsvariabele zetten

blastradius leest de key uit ANTHROPIC_API_KEY. Kies je besturingssysteem:

# eenmalig in deze terminal
export ANTHROPIC_API_KEY=sk-ant-...
python -m blastradius landschap.json --out rapport.html --ai

# vast: regel toevoegen aan ~/.bashrc
echo 'export ANTHROPIC_API_KEY=sk-ant-...' >> ~/.bashrc
# eenmalig in deze terminal
export ANTHROPIC_API_KEY=sk-ant-...
python -m blastradius landschap.json --out rapport.html --ai

# vast: regel toevoegen aan ~/.zshrc
echo 'export ANTHROPIC_API_KEY=sk-ant-...' >> ~/.zshrc
# eenmalig in dit PowerShell-venster
$env:ANTHROPIC_API_KEY = "sk-ant-..."
python -m blastradius landschap.json --out rapport.html --ai

# vast, nieuw venster daarna
setx ANTHROPIC_API_KEY "sk-ant-..."

3 · Het pakket installeren

pip install anthropic   # of: pip install -r requirements.txt

Draai je --ai zonder key of zonder pakket, dan meldt de tool dat kort op het scherm en maakt gewoon het rapport zonder die sectie. Een netwerkfout of rate limit laat de analyse ook nooit klappen.

Grenzen

  • Geen kans of frequentie. De analyse toont het gevolg bij uitval, niet hoe waarschijnlijk die uitval is.
  • Redundantie wordt alleen in de applicatielaag geteld, niet in de gedeelde infrastructuur eronder. Een component dat overal onder hangt zie je wel in de ranglijst.
  • De uitkomst is zo goed als de relaties in de bron. Ontbrekende koppelingen geven een onvolledig beeld; foute koppelingen komen als waarschuwing bovenaan het rapport terug.
